# Audience and delivery decisions

Model membership, contact-point resolution and activation output separately. One member can yield multiple output combinations; explain which count is being compared. Check current relationship/path restrictions and destination mapping rules before offering deployable configuration.

| Stage | Evidence |
| --- | --- |
| Segment preview | Inclusion/exclusion fixtures and full filter logic |
| Consent | Owner-approved meaning of unknown/revoked preferences and source provenance |
| Activation draft | Target, membership, contact-point priorities, fields and schedule |
| Publish | Actual run state, timing, counts and errors |
| Destination | Receipt, rejected records, duplicate handling and access |
| Stop/revoke | Future scheduling stopped; already-delivered copies handled separately |

The reviewed Data 360 target workflow can publish on the next scheduled target run after saving; linked activation-triggered flows can then send data onward. Do not treat Save as a harmless draft action. Use a local draft until the intended destination delivery is authorized.

## Destination evidence

A platform activation success is not destination acceptance or audience visibility. Trace eligible contact points, export status, destination processing/rejections and audience receipt independently. Count overlaps between missing contact points and opt-outs; do not subtract overlapping exclusions twice. Report exported/destination-unverified when that is all the evidence.
